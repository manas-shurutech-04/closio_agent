# Rules (non-negotiable)

**Every rule below is strict and is followed at every step, without exception** (user, 2026-10-15). These R-rules are about **how the agent is built**. The **agent's own rules** (what closio-agent does when it runs) are G1–G4 and A1–A14 in `project-context.md` (sections "Agent Git Rules" and "Agent Behaviour Rules"); the team copy, with each rule's decision and where it's applied, is `docs/agent-rules.md`; the ones the AI must follow in every session are also in `AGENTS.md`. All three are updated together.

| # | Rule | How it is applied |
|---|------|-------------------|
| R1 | **No hallucination.** | Stick strictly to user instructions and verified facts. Options and suggestions are welcome but must be clearly labelled as suggestions, never mixed into what is implemented or presented as fact. If unsure, ask. |
| R2 | **Docs always up to date.** | Every step that changes anything updates the relevant docs in the same step. A step is not done until its docs are updated. |
| R3 | **Draft before implementing.** | Before finalising anything, present a draft of what will be implemented. Implement only after the user explicitly approves. |
| R4 | **No filler or progress messages.** | Don't spend tokens narrating progress ("now doing X…"). Output only what matters: drafts, questions, results. |
| R5 | **Build memory is separate from the agent's own memory.** | `build-memory/` is used at every step of building. The agent's memory while it runs is designed and stored separately. |
| R6 | **Ask when confused.** | Ask questions wherever a requirement is unclear, and reach common ground before proceeding. |
| R7 | **Advise proactively.** | The user is new to building AI agents, so suggest better approaches and best practices wherever they apply (labelled as suggestions, per R1). |
| R8 | **Always read the core files.** | At every step, always read `build-memory/README.md` and `build-memory/rules.md`. |
| R9 | **Read the other files only when needed.** | Read the other build-memory files only when the step needs them, so the token cost stays low as the files grow. |
| R10 | **Update after every step.** | After each step, update the build-memory files the step touched and add an entry to `history.md`. |
| R11 | **Record each decision in full only once.** | The full record (reasons and rejected options) lives in the team design-decisions doc. `decisions.md` holds one line per decision plus a link to that record. |
| R12 | **Keep language simple.** (user, 2026-10-10) | In every output and doc: short sentences, plain words, no jargon unless needed (and explain it when used). Don't overcomplicate. |
| R13 | **Use relevant names.** (user, 2026-10-10) | Every name (commands, files, folders, tests) must say what the thing does. No placeholder names such as "hello". Commands don't contain "closio"; they start with `flow-` (D43). |
| R14 | **Node v22 for closio-agent; each repo on its own version.** (user, 2026-10-10; repo part changed 2026-10-14) | Always `nvm use v22` before starting Claude Code (or Codex) for this project, and before any node/npm/script command of closio-agent itself. **Code repos run on their own Node version** (`node_version` in `config/repos/<repo>.yaml`, from the Dockerfile): `nvm use <version>` (and `nvm install <version>` if missing) before running anything in a repo. Same as agent rules A9 and A13 (D41, D52). |
| R15 | **Full doc sweep at every prompt.** (user, 2026-10-14: "update these docs at each prompt"; repeated 2026-10-15: "keep the documents updated with each command") | At the end of **every** prompt that changes anything (code, a decision, an answer, a finding), before replying: **(1)** go through every file in the list below and update whatever the change touches, not only the obvious one; **(2)** search all of them for the words of what changed (old names, old statuses like "not built yet", "planned", "pending", old values) and fix every outdated line; **(3)** in `design-decisions.md`, add new decisions **and** update the status lines of older decisions the change affects; **(4)** in `open-questions.md`, move answered items to Resolved; **(5)** say in the reply which files were updated. Files: `README.md`, `AGENTS.md`, `docs/README.md`, `docs/setup-guide.md`, `docs/architecture.md`, `docs/commands.md`, `docs/agent-rules.md` (a rule added or changed, or a command that starts applying one), `docs/changelog.md`, `docs/design-decisions.md`, `build-memory/project-context.md` (plan + docs tables, answers), `decisions.md`, `open-questions.md`, `environment.md`, `history.md`, `README.md` (index). A step is not done until this sweep is done. |
| R16 | **Point to the right files.** (user, 2026-10-15: "point me to the right files only") | Whenever a reply mentions a change, a rule or a fact, name the exact file it's in, as a link with the line number when it helps (e.g. `build-memory/rules.md:21`). Never write "added X to R15" without the file, and never let a reply suggest something is in a file the user is looking at when it's somewhere else. This also applies to the R15 list of updated files. |
