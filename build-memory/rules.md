# Rules (non-negotiable)

**Every rule below is strict and is followed at every step, without exception** (user, 2026-10-15). These R-rules are about **how the agent is built**. The **agent's own rules** (what closio-agent does when it runs) are G1–G4 and A1–A28 in `project-context.md` (sections "Agent Git Rules" and "Agent Behaviour Rules"); the team copy, with each rule's decision and where it's applied, is `docs/agent-rules.md`; the ones the AI must follow in every session are also in `AGENTS.md`. All three are updated together.

| # | Rule | How it is applied |
|---|------|-------------------|
| R1 | **No hallucination.** | Stick strictly to user instructions and verified facts. Options and suggestions are welcome but must be clearly labelled as suggestions, never mixed into what is implemented or presented as fact. If unsure, ask. |
| R2 | **Docs always up to date.** | Every step that changes anything updates the relevant docs in the same step. A step is not done until its docs are updated. |
| R3 | **Draft before implementing.** | Before finalising anything, present a draft of what will be implemented. Implement only after the user explicitly approves. |
| R4 | **No filler or progress messages.** | Don't spend tokens narrating progress ("now doing X…"). Output only what matters: drafts, questions, results. |
| R5 | **Build memory is separate from the agent's own memory.** | `build-memory/` is used at every step of building. The agent's memory while it runs is designed and stored separately. |
| R6 | **Ask when confused.** | Ask questions wherever a requirement is unclear, and reach common ground before proceeding. |
| R7 | **Advise proactively.** | The user is new to building AI agents, so suggest better approaches and best practices wherever they apply (labelled as suggestions, per R1). |
| R8 | **Always read the core files.** | At every step, always read `build-memory/README.md` and `build-memory/rules.md`. |
| R9 | **Read the other files only when needed.** | Read the other build-memory files only when the step needs them, so the token cost stays low as the files grow. |
| R10 | **Update after every step.** | After each step, update the build-memory files the step touched and add an entry to `history.md`. |
| R11 | **Record each decision in full only once.** | The full record (reasons and rejected options) lives in the team design-decisions doc. `decisions.md` holds one line per decision plus a link to that record. |
| R12 | **Keep language simple.** (user, 2026-10-10) | In every output and doc: short sentences, plain words, no jargon unless needed (and explain it when used). Don't overcomplicate. |
| R13 | **Use relevant names.** (user, 2026-10-10) | Every name (commands, files, folders, tests) must say what the thing does. No placeholder names such as "hello". Commands don't contain "closio"; they start with `flow-` (D43). |
| R14 | **Node v22 for closio-agent; each repo on its own version.** (user, 2026-10-10; repo part changed 2026-10-14) | Always `nvm use v22` before starting Claude Code (or Codex) for this project, and before any node/npm/script command of closio-agent itself. **Code repos run on their own Node version** (`node_version` in `config/repos/<repo>.yaml`, from the Dockerfile): `nvm use <version>` (and `nvm install <version>` if missing) before running anything in a repo. Same as agent rules A9 and A13 (D41, D52). |
| R15 | **Full doc sweep at every prompt.** (user, 2026-10-14: "update these docs at each prompt"; repeated 2026-10-15: "keep the documents updated with each command") | At the end of **every** prompt that changes anything (code, a decision, an answer, a finding), before replying: **(1)** go through every file in the list below and update whatever the change touches, not only the obvious one; **(2)** search all of them for the words of what changed (old names, old statuses like "not built yet", "planned", "pending", old values) and fix every outdated line; **(3)** in `design-decisions.md`, add new decisions **and** update the status lines of older decisions the change affects; **(4)** in `open-questions.md`, move answered items to Resolved; **(5)** say in the reply which files were updated; **(6) rule files, every time** (user, 2026-10-19: "if you're making any change, then the rule set files are also updated at the same time"; and Codex too: "codex should not skip this as well", so `AGENTS.md` rule 21): whatever the change (a command, a script, a setting, a decision, a doc), go through every rule file in the same step and update each line the change touches: `rulesets/` (every ruleset file: its steps, the commands and step numbers it names, the scripts and checks it describes), `AGENTS.md`, `docs/agent-rules.md` (its "where it's applied today" column too), the agent rules in `build-memory/project-context.md`, `build-memory/rules.md`, and the pre-approvals `.claude/settings.json` and `.codex/rules/closio-agent.rules` (a new or renamed script, a new tool a command uses); in the reply, name each rule file: changed (and what), or checked with nothing to change; **(7) status words, every time** (user, 2026-10-19: "make sure these commands update the right places everytime without failure"): when something is built, tested by the user or changes state, update its status in every place that names it: its row in the command list of `docs/commands.md`, its decision's Status line in `docs/design-decisions.md` and its line in `decisions.md`, its row in the build plan in `project-context.md`, the status line of `docs/agent-rules.md`, `open-questions.md` and `history.md`; `bash scripts/help.sh check` (also run by `flow-doctor`) fails while a rule file calls a built command "coming" or "not built yet" ([D75](../docs/design-decisions.md#d75)). Files: `README.md`, `AGENTS.md`, `docs/README.md`, `docs/setup-guide.md`, `docs/architecture.md`, `docs/commands.md`, `docs/agent-rules.md` (a rule added or changed, or a command that starts applying one), `docs/user-guide.md` and its Claude artifact (a command added or changed, rule R17), `docs/jira-card-template.md` (a card rule changes), `rulesets/` (every ruleset file, at every change: step 6), `.claude/settings.json` and `.codex/rules/closio-agent.rules` (step 6), `docs/changelog.md`, `docs/design-decisions.md`, `build-memory/project-context.md` (plan + docs tables, answers), `decisions.md`, `open-questions.md`, `environment.md`, `history.md`, `README.md` (index). A step is not done until this sweep is done. |
| R18 | **Rules and memory before every step of the card phases.** (user, 2026-10-17: "before every phase… starting with C, you need to always check the memory, the rules, and the user memory… No rules are skipped, nothing is left out") | Before **every step** of drafting, building, testing or documenting a card piece (C1–C6): (1) re-read `build-memory/README.md` and `rules.md` (R8), `AGENTS.md`, the agent rules in `project-context.md` / `docs/agent-rules.md` (G1–G4, A1–A28), and the decisions the step touches (D61 and later); (2) run `bash scripts/memory.sh for <phase> all` and read the **user-created memory** entries (made with `flow-memory`, in `local/memory/`); (3) write down, before doing the step, which rules and entries apply to it, and check each one off when the step is done. The same check is built into every card-phase command as rule A17. |
| R17 | **Every flow command is listed everywhere.** (user, 2026-10-17: "all the flow commands are listed within the help command as well as in the artifact. That's a hard rule") | A new or changed flow command isn't done until, in the same step: its `## Usage` block in its `SKILL.md` (what `flow-help` shows) and, when it takes arguments, its `argument-hint` line (what Claude Code's `/` menu shows; user, 2026-10-18), its place in a `flow-help` group (the `GROUP_` lines in `scripts/help.sh`), its section in `docs/commands.md`, its section and index row in `docs/user-guide.md`, and the Claude artifact of the guide updated from `docs/user-guide.md` with the guide's "mirrored" line set (the date and every command). `bash scripts/help.sh check`, also run by `flow-doctor`, fails until it's done. Only Claude Code can reach the artifact; a change made in Codex is finished in Claude Code. Also `AGENTS.md` rule 11, D60. |
| R16 | **Point to the right files.** (user, 2026-10-15: "point me to the right files only") | Whenever a reply mentions a change, a rule or a fact, name the exact file it's in, as a link with the line number when it helps (e.g. `build-memory/rules.md:21`). Never write "added X to R15" without the file, and never let a reply suggest something is in a file the user is looking at when it's somewhere else. This also applies to the R15 list of updated files. |
