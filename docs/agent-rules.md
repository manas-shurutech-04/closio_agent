# Agent Rules

Every rule closio-agent follows when it runs, in one place. **Every rule is strict.** Each one links to the decision that explains why, and says where it's applied today.

- **Git rules (G1–G4):** how the agent uses git.
- **Behaviour rules (A1–A31):** everything else.
- **`AGENTS.md` column:** the rules the AI must follow in every session are also written in [`AGENTS.md`](../AGENTS.md), which Claude Code and Codex read at the start of every session ([D45](design-decisions.md#d45)). The number is the rule's number there.
- **Your user memory never overrides these rules** (A8). If one of your memory entries disagrees with a rule, the agent tells you and follows the rule.
- The rules for **building** closio-agent (R1–R19) are a different list, in [build-memory/rules.md](../build-memory/rules.md). Three of them are also in `AGENTS.md`, so a change made in Codex follows them too: rule 11 (every command listed everywhere, R17), rule 21 (the rule files and status words updated with every change, R15; [D75](design-decisions.md#d75)) and rule 28 (the builder's doc check: only on the builder's Mac, never in a card session, R19; [D89](design-decisions.md#d89)).

> Status (2026-10-23): every command is built: the setup commands (incl. `flow-setup-repo`, `flow-memory`, `flow-check-card`, `flow-help`) and every card phase: the pick-up, the plan, the development, the checks, the push and the after-merge step (`flow-start`, `flow-develop`, `flow-verify`, `flow-ac-check`, `flow-push`, `flow-review`, `flow-finish`, `flow-qa`, `flow-status`). SCRUM-540 went through every phase, from pick-up to Ready for Test (2026-10-19). Since 2026-10-21, `flow-push` checks every AC again when its rebase brought newer code or had a conflict (D83). Since 2026-10-23, the card rules (A29) are added to every prompt about a card by a hook, and the card's folder is saved to GitHub after every reply (A30), in Claude Code and Codex. The commands switch to the Jira API by themselves when the Jira connector isn't there (A31). Also since 2026-10-23, one call after every step, with the rules read in full at a command's start and again only when they changed or after a summary (A17, D91); and faster with the same checks (D90): fewer question rounds before the plan, a shorter plan and the quick check by default for a small card, servers started in the background and reused, a one-repo card's tests first, and read-only git without prompts.

| G3 | Develop together first, then make atomic commits. Never push everything as one commit. | [D10](design-decisions.md#d10) | — | Built (C3): `flow-develop` develops together and never commits; built (C5): `flow-push` proposes the atomic commits, the user approves them, `scripts/ship.sh commit` makes them |
